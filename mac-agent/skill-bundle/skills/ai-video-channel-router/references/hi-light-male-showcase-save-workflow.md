# Hi-light 男生展示面保存与生产流程

当用户要保存或生产 Hi-light 男生展示面、形象展示、朋友圈展示视频时使用，尤其适用于由人脸图、半身图或全身参考图生成的视频。

## 核心规则

- 生产目标：做一条有展示价值的男生形象视频，不是简单“让照片动一下”。根据原图选择最酷且可信的动作，例如从蹲姿起身、抓住车把、跨上摩托、落到骑行姿态，最后停在自信的 3/4 英雄脸。
- 默认流程：任何新的静图男生展示面视频，都先做故事板，再做首帧/身份锚定，然后提交 Hi-light，最后下载、裁剪和质检。
- 故事板是每张源图的默认生产载体。用故事板规划身份、服装、场景、动作路线、镜头路线、灯光、声音和画面稳定性。
- 本流程把 Hi-light 当作只能稳定吃“首帧图参考”的渠道。因为它不能可靠吃多参考帧，所以要把生产计划压缩进高信息量故事板/电影制作板，并用提示词告诉模型具体执行什么。
- 默认故事板为 6-9 帧。简单 10 秒朋友圈展示面用 6 帧；动作更丰富、交付价值更高、涉及复杂姿态或车辆/道具过渡时用 8-9 帧。
- 如果源图是侧脸、裁脸、人脸网格、遮罩脸，或不是强正脸身份参考，就用故事板先建立清楚的 3/4 或正脸锚点和动作峰值，再进入 Hi-light。
- 完整展示动作通常为 10-15 秒。5 秒只用于用户明确要求的微动测试。
- 交付物只保存真实 Hi-light 视频文件：直接下载的 mp4、处理后的 mp4 和经过验证的输出。
- 如果 UI 卡在 5s 但任务需要完整动作，提交前停止并标记为 `duration_setting_blocked`，不要静默消耗点数生成不足时长的视频。
- 优先使用当前可见且包含目标 `history_id` 的 Chrome/CDP 标签页。不要浪费时间在历史抽屉为空的热登录席位上。
- 从已登录页面上下文请求 `https://wiseapi.hi-light.ai/v1/history/getHistoryList?history_type=1`，并带上页面 `localStorage.Authorization` header。
- 只下载 `status == 3` 且 `source_url` 非空的历史项。
- 如果用户说有两个视频，但账号历史/API 只返回一个成功项，其余是失败卡，就保存这一个真实成功项，并说明第二个成功视频源不可用。

## 过人脸 / 加白线锁定步骤

- 默认不做过人脸/加白线。原图确认、故事板、视频提示词和 Hi-light 首帧上传都优先使用干净原图。
- 用户在当前任务提到“加白线 / 白线效果 / 过face / 过人脸”时，必须使用 `C:\Users\lsb\Desktop\过face.url`（当前解析目标 `http://127.0.0.1:9093/face`）做一次人脸锚定/加白线；该说法就是对本次指定图片的具体授权。不手工画线，不用临时脚本或其他本地图像工具画线。
- 需要保持人脸一致性且已决定使用该步骤时，只把用户指定的最终首帧图送入 9093 face 服务，导出服务生成的过人脸/加白线图，再把该输出作为 Hi-light 的 `首帧图` 上传。
- 如果快捷方式缺失、9093 face 服务不可访问、页面无法导出或输出明显错误，记录 blocker `face_line_service_not_ready`，不要绕过成手动画线或其他本地描边。
- Hi-light 下载后必须检查开头约 27 帧。白线残留只裁到最后一帧可见白线之后再加 1 帧安全余量；不要默认固定裁 1 秒。
- 白线图只是生成控制图，不是最终展示图。交付前必须用抽帧确认开头白线已经消失，不能把白线残留版标记为 clean。

## 故事板优先生产路线

当用户要用静图生成新的男生展示面视频时，提交 Hi-light 前先使用 `image2-storyboard-video`、`ai-video-storyboard`、`ai-video-fundamentals-skill` 和 `ai-video-firstframe-workflow`。

必要预检只做内部使用，不把“资产卡”作为用户侧交付物，除非用户主动要求。对外用简洁的素材锁定说明即可：
- 素材锁定：脸部锚点、发型、服装、配饰、身体比例、车辆/道具、地点和光线。
- 故事板意图：一个完整镜头，包含清楚的起势、推进、峰值和收束姿态。
- 故事板帧数：最少 6 帧，默认 6-9 帧。
- 制作板结构：原图身份/参考区、6-9 个电影帧、镜头路线/动作箭头、服装/脸/场景锁定、灯光说明、声音说明和画面稳定性说明。
- 身份策略：原图负责锁定身份、服装和车辆/道具；故事板在需要时补足 3/4 或正脸动作清晰度。
- 动作策略：写清楚人物为什么动、手接触哪里、肩膀/躯干/腿怎么走、头发和衣料怎么动、眼神落在哪里、最终英雄姿态是什么。
- Hi-light 首帧策略：如果用故事板作为首帧参考，最终视频提示词要说明模型应该从故事板执行什么：干净电影镜头、连续动作、身份稳定、服装稳定、场景稳定、最终英雄姿态。

摩托赛车服图的推荐镜头：
- 起势：人物蹲在白色运动摩托旁，保持同样黑发和黑白赛车服。
- 推进：右手抓住车把，左肩抬起，身体向镜头转过来。
- 峰值：人物站起并用一个干净利落的动作跨上摩托。
- 收束：坐上或半跨在摩托上，露出 3/4 脸，自信冷静，摩托灯光稳定。

故事板是压缩后的制作计划，最终视频应该像一个完成度高的电影镜头，而不是制作板本身。

## Hi-light 完整提示词规则

男生展示面视频提交给 Hi-light 的最终提示词必须完整、以执行为导向，不能压缩成三段极简提示词。提示词要先告诉模型应该创造什么：

- 成片目标：10 秒视频的情绪、风格、自信程度和展示价值。
- 参考图/故事板执行方式：上传图是规划和参考材料，最终视频应该变成干净的电影镜头。
- 身份和服装锁定：脸、发型、身体比例、服装、配饰、车辆/道具保持一致。
- 场景锁定：地点、时间、光线方向、天气、海风/海浪和背景连续性保持一致。
- 时间轴节奏：用时间戳写清完整 10 秒镜头的起始姿态、推进动作、峰值动作和结尾英雄姿态。
- 镜头运动：焦段、构图、推拉、环绕、摇移、机位高度、视差和景深。
- 身体/脸/衣料/头发运动：手、肩、躯干、腿、眼神、表情、衣料飘动和头发运动。
- 声音设计：让模型生成匹配场景的原生音效，例如海边场景里的海浪和风声。
- 画面稳定性护栏：最终画面保持干净、连续、身份稳定、服装稳定、场景稳定，不出现制作板元素。

## 下载和裁剪

- 直接用 `Invoke-WebRequest` 或浏览器下载 `source_url`。
- 用户需要处理版输出时，原始下载放在 `_raw` 子文件夹。
- 拿到 `source_url` 后优先使用内置脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\lsb\.codex\skills\ai-video-channel-router\scripts\save-hilight-showcase-video.ps1" -SourceUrl "<mp4-url>" -OutputDir "C:\Users\lsb\Pictures\男生展示面\成片\客户1视频" -BaseName "客户1视频_01" -TrimSeconds 0.125 -HistoryId 323728471228416 -CdpPort 9223
```

- 如果用户要求去掉开头白色人脸线，不要默认裁 1 秒。先检查开头帧窗口，找到真实裁点：
  - 至少生成前 `27` 帧抽帧检查图。这是 QA 检查窗口，不是裁剪长度。
  - 找到仍有明显白色人脸网格/遮罩线的 `last_bad_frame`。
  - 精确裁点从 `last_bad_frame + 1` 开始。
  - 可多留一帧安全余量。24fps 下，如果只有第 `0` 和 `1` 帧坏，精确裁点是 `2/24 = 0.083s`，安全裁点是 `3/24 = 0.125s`。
  - 没有抽帧检查图证明坏帧持续更久时，不要在未确认下裁掉超过 `0.30s`。
- 短裁剪优先重编码，保证裁点准确：

```powershell
ffmpeg -y -ss 0.125 -i raw.mp4 -map 0:v:0 -map 0:a? -c:v libx264 -preset veryfast -crf 18 -c:a aac -b:a 192k -movflags +faststart out.mp4
```

## 用户输出约定

- 最终文件写入用户明确要求的文件夹。
- 这个用户的男生展示面常用输出目录：

```text
C:\Users\lsb\Pictures\男生展示面\成片\客户1视频
```

- 客户1 的故事板原图、9093 face 加线图等可复用素材，默认同步到素材目录：

```text
C:\Users\lsb\Pictures\男生展示面\素材图\客户1
```

- 使用清楚命名，例如 `客户1视频_01_去白线开头.mp4`。
- 原始下载放 `_raw`，可选 QA 静帧放 `_qa`。
- Hi-light `history_id` 可能超过 32 位整数范围。脚本必须用 `long`/string 存储，不能用 `int`。
- 如果脚本由 Windows PowerShell 5.1 执行，除非已确认文件 BOM，否则 `.ps1` 内避免硬编码中文后缀。优先生成 ASCII 名如 `_trim125ms_`，验证后再用 PowerShell 命令改成用户侧中文文件名。

## 验证

- 每个最终视频都用 `ffprobe` 验证：文件存在，裁剪后时长约等于原始时长减去 manifest 里的 `trim_seconds`，有视频流，分辨率符合预期，源文件有音频时保留音频。
- 可行时记录 SHA256 和文件大小。
- 视觉 QA：裁剪后抽取第一帧静图，只用于确认开头白线已消失。除非用户要求，静图不是交付物。

## 生产观察

- 2026-07-04 成功运行时，用户可见 Chrome 标签在 CDP `9223`，热登录席位 `9401` 虽然登录但历史抽屉为空。下载任务要路由到包含目标 `history_id` 的标签页，不要盲目路由到有点数的热席位。
- 浏览器页面里的 `fetch()` 可能受站点包装或 CORS 行为影响而不稳定。如果页面执行返回空历史，从页面读取 `localStorage.Authorization`，再用 Playwright `context.request.get()` 携带 `Authorization` 和 `Referer: https://app.hi-light.ai/` 请求。
- 真实历史列表可能同时包含一个成功视频和多个失败卡。只有 `status == 3 && source_url` 才是可下载成功项；失败卡不阻塞保存成功项。
- 对人脸网格源图，Hi-light 可能在初始过渡后生成干净人脸。提示词中让网格消失，然后检查前 27 帧，只裁到最后一个硬白网格帧后一帧安全余量，并目检裁剪后的第一帧和抽帧检查图。
- 每次运行在 `_ledger` 下写 JSON manifest，记录 source URL、history ID、裁剪秒数、原始/最终路径、时长、哈希、流信息和验证布尔值。汇报基于 manifest，不基于意图。
