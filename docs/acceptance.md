# acceptance.md — 验收清单（v0.1 整改版）

> 用法：每完成一轮整改，逐条勾选并附**命令 + 输出证据**。任一条未过，不得宣布"可用"。

---

## A. 可用基线（P0：决定"网站能不能用"）

- [ ] A1 `GET https://sd2.cauai.fun/api/health` 返回 200 且字段收敛（不含内部迁移/worker 细节）
- [ ] A2 已登录用户可访问 `/`，工作台三栏正常渲染，无 console 报错
- [ ] A3 提交一次真实 i2v 任务，紫域侧返回 `job.id`，本地 `provider_jobs` 落库
- [ ] A4 任务终态（completed）后产物可下载，链接有效期 ≥ 24h
- [ ] A5 刷新页面后任务列表与素材库状态保持（真实持久化）
- [ ] A6 任务失败时展示渠道原因码 + 可一键复用参数重试
- [ ] A7 积分：下单冻结 → 终态结算 → 失败按规则退款，`credit_ledger` 可追溯

## B. 数据层（P0）

- [ ] B1 Postgres 中业务表数量 ≥ 迁移预期，`information_schema` 查询结果已记录
- [ ] B2 应用容器含完整的 `POSTGRES_DB` 等连接变量（脱敏核对键名与长度）
- [ ] B3 遗留 `niannian-auth.sqlite` 完成迁移或归档，且代码中不再引用
- [ ] B4 生产库每日备份任务存在，且已成功导出过一份可恢复备份
- [ ] B5 数据目录不再承载长期产物（临时文件有清理任务）

## C. 渠道与模型（P0）

- [ ] C1 模型目录来自运行时 `GET /api/v1/models`，代码中无硬编码 `zy_model_*`
- [ ] C2 模拟模型失效（改用无效 ID）时，系统回退 `activeModelId` 并提示用户
- [ ] C3 未配置凭据的渠道在 UI 中不出现
- [ ] C4 素材数量/类型按 `model.assetLimits` 校验，超限有明确提示
- [ ] C5 提示词为空/超长时前端拦下，服务端二次校验
- [ ] C6 渠道"系统异常"时自动重试 1 次，仍失败则退款

## D. 工程与质量门（P1）

- [ ] D1 源码已入 Git 仓库，`main` 受保护，禁止直推
- [ ] D2 `npm run verify` 存在且串联：typecheck → lint → 单测 → 契约测试 → secret 扫描 → build
- [ ] D3 CI 在 PR 上运行并作为合并门禁
- [ ] D4 `.env.production` 为 LF、无 BOM、无污染行，且通过键名完整性校验脚本
- [ ] D5 存在 ESLint 配置并可用（不再只有 `tsc --noEmit`）
- [ ] D6 发布有回滚方案：上一可用镜像 tag + 迁移回滚脚本已验证
- [ ] D7 `robots.txt` / `sitemap.xml` 已提供

## E. 安全与合规（P1）

- [ ] E1 全仓 secret 扫描通过
- [ ] E2 日志中无密钥、OTP、会话令牌、用户邮箱明文
- [ ] E3 客户端 bundle 中不含任何渠道凭据
- [ ] E4 CSRF/来源校验覆盖所有写接口
- [ ] E5 生成内容涉及地图时符合国家规范（完整中国地图）

## F. 变更风险分级（每次改动必填）

| 等级 | 范围 | 要求 |
|---|---|---|
| L0 | 文案、样式、文档 | 自测 + 截图 |
| L1 | 单模块逻辑 | 单测 + 1 人 review |
| L2 | 跨模块 / 接口变更 | 契约测试 + review + 文档同步 |
| L3 | 鉴权 / 数据 / 部署 / 架构 | 安全审计 + 回滚方案 + 线上验证 + 双人 review |
