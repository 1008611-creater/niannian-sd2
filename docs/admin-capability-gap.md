# 后台运营能力：现状盘点与差距分析

> 2026-09-18　|　老大的原话："我要用这个管理员界面肯定优先是想用来**看数据**，还有**管理模型、定价**等操作，然后**素材库**、**团队**、**项目**、**模板素材**的管理都需要做好，**不只是管理员界面，对应的源站也需要开发好**。"
> 本文只做两件事：**把现状摆清楚（事实）**、**把要补什么说清楚（差距）**。实施按 `docs/implementation-plan.md` 分期推进。

---

## 一、一句话结论

**现在的后台只能"看任务"，不能"做生意"。**
它本质是给**运维排障**用的（任务队列、worker 心跳、渠道连通性），不是给**运营做生意**用的。
你要的 7 件事里，**3 件完全没有、2 件只有半成品、2 件是空壳**。

---

## 三、差距的根因（一句话）

这套代码的后台是**为"内部排障"设计的**，不是为"对外运营"设计的：
它关心"任务卡在哪了、worker 还活着吗"，不关心"这个月赚了多少、哪个模型好卖、定价要不要调"。

要把它改造成运营后台，**不是补几个页面，而是要补一整套"运营数据模型"**——
上面缺的那 4 张表就是这套模型的地基。

---

## 四、建设方案（按主要矛盾排序）

### 优先级判断依据

**先做能决定"能不能做生意"的**：定价是钱、模型是卖什么、数据是看效果。
**团队最大最复杂，放最后**——它涉及权限模型重构，过早做会拖住前面。

### P0 — 运营地基（先做这个）

| 项 | 做什么 | 为什么先做 |
|---|---|---|
| **定价管理** | 新增 `pricing_rules` 表 + 后台改价 UI + `lib/credits.ts` 改为读库（带内存缓存，改价即生效） | 现在改一次价要发版重启，生意没法做 |
| **模型管理** | 新增 `model_overrides` 表（中文名、上下架、排序、标签、加价系数）+ 后台 UI；源站只展示 `enabled` 的模型 | 紫域的模型名是 `zy_model_a9725c...`，用户看不懂，也没法挑主推款 |
| **数据看板升级** | 趋势（日/周新增用户、出片量、成功率）、收入（充值/消耗）、成本（渠道点数）、失败原因分布、Top 模型 | 6 个静态数字做不了决策 |

### P1 — 内容与资产

| 项 | 做什么 |
|---|---|
| **素材库管理** | 管理员全局视图（缩略图、归属、大小、状态）+ 下架违规素材 + 设公共/推荐素材；`uploaded_assets` 加治理字段 |
| **项目管理** | 后台项目列表（归属、状态、资产数、创建时间）+ 异常项目处置 |

### P2 — 模板

| 项 | 做什么 |
|---|---|
| **模板素材** | `templates` 表（名称、封面、默认参数、提示词模板、适用模型）+ 后台 CRUD + 源站模板市场入口 |

### P3 — 团队（最大）

| 项 | 做什么 |
|---|---|
| **团队管理** | `teams` / `team_members` 表 + 邀请 + 角色（owner/admin/member）+ 团队内共享项目/素材 + 团队积分池（可选） |

## 五、每个能力都要成对的"后台 + 源站"

老大明确要求"**不只是管理员界面，对应的源站也需要开发好**"。
所以每一项都按这个矩阵验收，缺一半不算完成：

| 能力 | 后台（管理侧） | 源站（用户侧） |
|---|---|---|
| 定价 | 改价 UI、生效即所见 | 下单页显示实时价格、余额不足提示 |
| 模型 | 上下架、改名、排序 | 只展示已上架模型，显示中文名 |
| 素材 | 全局管理、违规下架 | 公共素材库可见、我的素材可管 |
| 团队 | 团队列表、成员管理 | 团队空间、共享项目、邀请入口 |
| 项目 | 项目列表、异常处置 | 项目创建/编辑/删除 |
| 模板 | 模板 CRUD | 模板市场、一键套用 |

## 六、风险与约束（先说清，别做到一半才发现）

1. ~~**改价不能影响在途订单**~~ → **已解决，且不是靠单价快照**：
   `credit_ledger` 已经记了每一笔**实际扣掉的金额**和 `task_id`，`refundTaskCredits` 按该金额退，
   与当前价目表无关。所以调价既不会让历史订单对不上账，也不会让退款算错。
   因此**没有**给 `video_tasks` 加单价快照列 —— 那会引入一次 Postgres `ALTER` 迁移，收益为零。（R32）
2. ~~**模型上下架要能兜底**~~ → **已解决**：合并目录会把「渠道列表里没有了、但我们还有配置」的模型
   标成 `source=override_only`，后台显示"渠道已移除"并可一键清除；源站不展示，
   下单返回 `MODEL_NOT_FOUND` 而不是打到渠道才发现失败。（R33）
3. **团队是最贵的**：一旦引入团队，权限判断要从"用户级"扩到"团队级"，
   `projects` / `uploaded_assets` 都要加归属维度，属于半次重构。**所以放 P3**。
4. **模板依赖模型**：模板要绑定适用模型，所以**模板排在模型管理之后**。
5. **每次上线都要重建镜像**：源码是预构建镜像，改完要 build + 换容器（约 2~3 分钟构建 + 10 秒重启）。
