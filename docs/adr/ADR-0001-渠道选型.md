# ADR-0001：MVP 只保留紫域单一渠道，模型动态拉取

- **日期**：2026-09-17
- **状态**：提议（待确认）
- **背景**：
  - 凭据矩阵显示：Seedance 未配置、MIMO 缺用户名/密码/Token、MIORA Cookie 为空且提交开关为 false、视频派发服务未配置；只有紫域 `ZIYU_API_KEY` 完整可用。
  - 紫域模型目录为**动态下发**（54 个模型，ID 形如 `zy_model_xxx`），历史任务中已出现 `model not found` 与 `unavailable for external api`。
- **决策**：
  1. MVP 阶段对外只暴露紫域一个渠道；未配置凭据的渠道在 UI 与 `/api/providers` 中**不出现**。
  2. 禁止在代码或文档中硬编码具体模型 ID；模型目录运行时拉取，缓存 ≤ 5 分钟。
  3. 下单前校验模型有效性，失效时回退 `activeModelId` 并向用户提示。
  4. 前端只展示 3~5 个能力档位（省钱/均衡/高质量/长时长/图片），由规则映射，不暴露渠道内部线路名。
- **后果**：
  - 正面：消除"点了没反应"的假能力；消除模型失效导致的硬失败。
  - 负面：单一渠道供应商锁定；渠道停摆即服务不可用（见 R15，需降级提示与备用渠道预案）。
